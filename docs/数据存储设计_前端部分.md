## 数据加载策略

### 1.1 分层加载架构

```
┌────────────────────────────────────────────────────┐
│                   首次加载（< 2s）                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐   │
│  │ Idea列表  │ │ 热点排名  │ │ 系统状态(统计数)  │   │
│  │ (60条)   │ │ (Top10)  │ │                  │   │
│  └──────────┘ └──────────┘ └──────────────────┘   │
│        数据量: ~80KB (极轻量，快速首屏)               │
└────────────────────────────────────────────────────┘
                         │
                         ▼
┌────────────────────────────────────────────────────┐
│                 二级加载（用户交互触发）               │
│  ┌──────────┐ ┌──────────────┐ ┌──────────────┐   │
│  │ 问题/方法 │ │ 森林图数据     │ │ 论文卡片索引  │   │
│  │ 聚类数据  │ │ (nodes+links) │ │ (300条摘要)  │   │
│  └──────────┘ └──────────────┘ └──────────────┘   │
│        数据量: ~2MB (页面核心数据)                    │
└────────────────────────────────────────────────────┘
                         │
                         ▼
┌────────────────────────────────────────────────────┐
│                 按需加载（点击触发）                    │
│  ┌──────────┐ ┌──────────────┐ ┌──────────────┐   │
│  │ 单Idea   │ │ 单个论文详情   │ │ 关联论文推荐  │   │
│  │ 推理链    │ │ (含figures)  │ │              │   │
│  └──────────┘ └──────────────┘ └──────────────┘   │
│        数据量: 每请求 ~20-100KB                       │
└────────────────────────────────────────────────────┘
```

### 1.2 各阶段加载详情

| 阶段 | 触发条件 | 加载数据 | API对应 | 预期耗时 |
|------|----------|----------|---------|----------|
| 首次 | 页面打开 | Idea列表 + 热点 + 状态 | `/api/ideas?page_size=60` + `/api/trends/hot-topics` + `/api/status` | < 1s |
| 二级-森林 | 切换到森林视图 | 森林图节点+连线 | `/api/graph/forest` | < 500ms |
| 二级-仪表盘 | 切换到仪表盘 | 问题/方法聚类 + 论文年份统计 | `/api/trends/temporal` + 本地聚合 | < 300ms |
| 二级-论文列表 | 打开论文列表 | 论文摘要列表第1页 | `/api/papers?page=1` | < 300ms |
| 按需-Idea | 点击Idea节点 | 单Idea推理链 | `/api/graph/root?idea=FI001` | < 300ms |
| 按需-论文 | 点击论文节点 | 论文详情 | `/api/papers/{id}` | < 200ms |
| 按需-推荐 | 论文详情页展开 | 关联推荐 | `/api/papers/{id}/related` | < 200ms |

### 1.3 加载状态UI

| 状态 | UI表现 |
|------|--------|
| 加载中 | 显示 loading-orb 动画 + "正在唤醒 Idea Forest..." |
| 加载成功 | 渐变消失（opacity 0.3s过渡） |
| 加载失败 | 显示 error-screen："数据加载失败" + 错误描述 + "重试"按钮 |
| 部分失败 | 主内容显示，失败区域显示 "暂不可用" 标记 + "重试"按钮 |

## 内存缓存设计

### 2.1 缓存结构

```javascript
// 前端内存缓存（app.js state对象）
const cache = {
  // --- 一级缓存：总是驻留 ---
  ideas: [],                    // 60条Idea（含normalize后的计算字段）
  hotTopics: [],                // Top10热点问题
  systemStatus: null,           // 系统状态统计

  // --- 二级缓存：按需加载后驻留 ---
  forestGraph: { nodes: [], nodeById: Map, links: [] },
  microProblems: {},            // 145个微问题 Map<id, object>
  microMethods: {},             // 229个微方法 Map<id, object>
  paperList: {                  // 论文摘要列表（分页缓存）
    pages: new Map(),           // pageNum -> [paper摘要数组]
    total: 300,
  },
  temporalData: null,           // 时间趋势数据

  // --- 三级缓存：LRU淘汰 ---
  paperDetailCache: new LRUCache(30),    // 最近30篇论文详情
  rootGraphCache: new LRUCache(15),      // 最近15个Idea推理链
  relatedPapersCache: new LRUCache(30),  // 最近30个关联推荐结果
};
```

### 2.2 LRU缓存实现

```javascript
class LRUCache {
  constructor(maxSize = 30) {
    this.maxSize = maxSize;
    this.cache = new Map();  // Map保持插入顺序
  }

  get(key) {
    if (!this.cache.has(key)) return undefined;
    // 访问时移到末尾（最新）
    const value = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, value);
    return value;
  }

  set(key, value) {
    if (this.cache.has(key)) this.cache.delete(key);
    else if (this.cache.size >= this.maxSize) {
      // 删除最旧（Map第一个key）
      const oldestKey = this.cache.keys().next().value;
      this.cache.delete(oldestKey);
    }
    this.cache.set(key, { data: value, timestamp: Date.now() });
  }

  has(key) { return this.cache.has(key); }

  clear() { this.cache.clear(); }
}
```

### 2.3 缓存优先级

| 数据 | 缓存级别 | 淘汰策略 | 最大条目 | 理由 |
|------|----------|----------|----------|------|
| Idea列表 | 一级 | 不淘汰 | 60 | 核心数据，体积小(80KB) |
| 热点排名 | 一级 | 不淘汰 | 10 | 首屏必需 |
| 问题/方法聚类 | 二级 | 不淘汰 | 374 | 所有图表数据源 |
| 森林图数据 | 二级 | 不淘汰 | 1 | 当前视图必需 |
| 论文摘要列表 | 二级 | 分页保留 | 15页(300条) | 列表浏览体验 |
| 论文详情 | 三级-LRU | 最旧淘汰 | 30 | 体积大(含figures) |
| Idea推理链 | 三级-LRU | 最旧淘汰 | 15 | 计算量较大 |
| 关联推荐 | 三级-LRU | 最旧淘汰 | 30 | 随论文详情触发 |

## 本地存储设计

### 3.1 localStorage 用途

```
localStorage
├── vmr_user_prefs        JSON 用户偏好设置
├── vmr_view_state        JSON 上次浏览状态
└── vmr_recent_ideas      JSON 最近查看的Idea（最多10个）
```

### 3.2 用户偏好（`vmr_user_prefs`）

```json
{
  "theme": "dark",
  "language": "zh-CN",
  "default_view": "forest",
  "forest_filter": "all",
  "dashboard_idea": "FI001",
  "page_size": 20,
  "auto_refresh": true,
  "refresh_interval_minutes": 5
}
```

### 3.3 浏览状态恢复（`vmr_view_state`）

```json
{
  "last_view": "root",
  "last_idea_id": "FI001",
  "last_paper_id": null,
  "forest_transform": { "x": -45.2, "y": 23.1, "k": 1.14 },
  "root_transform": { "x": 128, "y": 145, "k": 0.84 },
  "root_filter": "all",
  "timestamp": "2026-07-07T10:30:00Z"
}
```

**恢复逻辑**：
1. 页面初始化时读取 `vmr_view_state`
2. 若 `timestamp` 距离当前 < 24小时，恢复上次视图
3. 若超过24小时或值为null，使用默认视图（森林）
4. `forest_transform` / `root_transform` 在每次变换时debounce写入（延迟500ms）

### 3.4 不适合 localStorage 的数据

| 数据 | 原因 | 替代方案 |
|------|------|----------|
| 论文详情(含figures) | 体积大，每个可达200KB | 内存LRU缓存 |
| Idea推理链 | 体积中等但变化频繁 | 内存LRU缓存 |
| 论文列表 | 数据可能更新 | 内存缓存 + 定时重载 |
| 图表聚合数据 | 计算结果，可从源数据恢复 | 不缓存，每次计算 |

## 数据更新策略

### 4.1 定时刷新

| 数据 | 刷新间隔 | 触发方式 | 理由 |
|------|----------|----------|------|
| 热点排名 | 5分钟 | `setInterval` 静默刷新 | 热点变化相对较快 |
| Idea列表 | 30分钟 | 用户切回森林视图时检查 | Idea评分可能因新论文变化 |
| 论文列表 | 30分钟 | 用户切到论文列表时检查 | 新论文可能入库 |
| 系统状态 | 5分钟 | `setInterval` 静默刷新 | 统计数可能变化 |
| 问题/方法聚类 | 24小时 | 页面加载时检查 | 聚类结构稳定 |

### 4.2 手动刷新

用户可通过以下方式触发手动刷新：

| 触发方式 | 刷新范围 | UI反馈 |
|----------|----------|--------|
| 点击"刷新"按钮(仪表盘) | 全部图表数据 | 按钮旋转动画 + 图表 fadeOut→fadeIn |
| 浏览器F5刷新 | 全部数据（重置缓存） | 完整加载流程 |
| 切换视图时 | 当前视图所需数据（检查新鲜度） | 若数据过期则显示loading |
| "检查更新"按钮 | 对比API版本号，提示是否有新数据 | toast提示 |

### 4.3 数据新鲜度判断

```javascript
const STALE_THRESHOLDS = {
  hotTopics: 5 * 60 * 1000,      // 5分钟
  ideas: 30 * 60 * 1000,          // 30分钟
  paperList: 30 * 60 * 1000,      // 30分钟
  systemStatus: 5 * 60 * 1000,    // 5分钟
  microClusters: 24 * 60 * 60 * 1000, // 24小时
  forestGraph: 30 * 60 * 1000,    // 30分钟
};

function isStale(cacheKey) {
  const entry = cacheTimestamps[cacheKey];
  if (!entry) return true;
  return Date.now() - entry > (STALE_THRESHOLDS[cacheKey] || Infinity);
}
```

### 4.4 版本兼容

当后端数据版本（`/api/status` 返回的 `data_version`）变化时：

1. 清空全部LRU缓存
2. 重置一级/二级缓存时间戳，触发全部重载
3. localStorage中清除 `vmr_view_state`（避免状态不兼容）
4. UI显示 "数据已更新，正在重新加载..." toast

## 离线降级策略

当前应用主要依赖本地JSON数据文件（`data/idea_graph/` 目录），因此天然支持离线运行：

| 场景 | 策略 |
|------|------|
| API不可用 | 降级到本地 `./data/*.json` 静态文件（`loadJson` 已有 fallback 参数） |
| 初次加载失败 | 显示错误页 + 重试按钮，允许用户手动指定数据路径 |
| localStorage不可用 | 静默跳过持久化（try-catch包裹所有localStorage操作） |
| 内存不足(LRU未实现) | 降级为简单Map，不做淘汰 |
